防火墙阻断排查手册
1. 故障现象
特定端口或 IP 访问失败，但同网段其他服务正常

报错关键字：Connection timed out、Connection refused、No route to host

抓包显示请求已发出，但目标端无响应或返回 RST

2. 可能原因
防火墙规则显式 DROP 或 REJECT 了目标流量

安全组或 ACL 未放行源 IP 或目标端口

NAT 策略错误，导致回包路径不一致

防火墙会话表满或连接数超限

3. 排查步骤
检查本机防火墙规则
执行：iptables -L -n -v 或 firewall-cmd --list-all
关注：是否有 DROP/REJECT 目标端口的规则，包计数是否增长
异常判断：匹配到 DROP 且计数增长说明被本机防火墙阻断

检查云安全组或网络 ACL
执行：在云控制台查看安全组入方向规则
关注：是否放行源 IP 和目标端口
异常判断：无放行规则或规则优先级错误会导致阻断

在中间设备抓包
执行：tcpdump -i eth0 host 目标IP and port 目标端口
关注：是否有 SYN 发出、是否有 SYN-ACK 返回
异常判断：只有 SYN 无 SYN-ACK 说明中间被丢弃

检查防火墙会话表
执行：conntrack -L | grep 目标端口
关注：会话状态和数量
异常判断：会话表满会导致新连接无法建立

4. 处理方案
本机防火墙：按变更流程添加放行规则，避免使用 iptables -F

安全组/ACL：添加允许源 IP 到目标端口的入方向规则

NAT 错误：修正 NAT 策略，确保往返路径一致

会话表满：调整 conntrack 最大连接数或优化超时时间

5. 注意事项
修改防火墙规则前必须走变更流程并记录原始规则。放行端口遵循最小权限原则，禁止放行 0.0.0.0/0 到高危端口。防火墙变更可能影响现有业务，操作后需验证关键业务连通性。
